# 주간 투자 기록 블로그 작성

매주 토요일 기준 시점의 구글 시트 데이터로 주간 투자 리포트 초안을 생성한다.

## 실행 지시

아래 단계를 **순서대로** 실행한다. 각 단계 완료 후 다음으로 넘어간다.

---

### 1단계: 프로젝트 맥락 파악 (병렬 실행)

아래 파일을 **병렬로** 읽는다:

- `CLAUDE.md` — 아키텍처, frontmatter 스키마 확인
- `README.md` — 워크플로우, 시트 구성 확인
- `docs/preview/` 디렉토리 목록 — 기존 초안 목록
- `content/posts/2026/` 디렉토리 목록 — 발행본 목록

#### 1-A. 사용자 수정 패턴 학습 (필수)

`content/posts/2026/` 의 글은 **사용자가 Claude의 초안을 읽고 직접 수정해서 발행한 결과물**이다. 이 디렉토리가 어투·구조의 **단일 진실 공급원(SSOT)** 이 된다.

다음을 **병렬로** 읽는다:

1. **가장 최근에 발행된 포스트 1개** (예: `April-week4-record.md`) — 이번 글의 구조·표 형식·섹션 순서 템플릿
2. **그 직전 발행본 1~2개** (예: `April-week3-record.md`, `April-week2-record.md`) — 사용자 어투의 일관성 확인
3. **같은 슬러그의 `docs/preview/` 초안이 있다면 함께 읽고 diff 학습** — Claude가 쓴 원안 → 사용자가 수정한 발행본을 비교하여, 사용자가 **추가·삭제·재작성한 패턴**을 식별한다

학습 항목:

- **삭제 경향**: 어떤 표현·문장을 사용자가 잘라냈는가? (과장된 형용사? 불필요한 메타 코멘트? 중복 요약?)
- **추가 경향**: 사용자가 직접 보탠 문장의 톤·길이·관점은?
- **재작성 경향**: 같은 사실을 사용자가 다르게 표현했다면, 그 어순·종결어미·서술 방식을 학습
- **구조 변경**: 사용자가 섹션을 합치거나 순서를 바꿨다면 그 규칙을 따른다

이 학습 결과는 6단계 초안 작성 시 **반드시 반영**한다. Claude가 쓰던 어투를 그대로 재사용하지 말고, 발행본의 어투에 맞춘다.

### 2단계: 구글 시트 데이터 가져오기

```bash
node scripts/fetch-google-sheet.mjs 1V9N1racDnSmvHuGkMHFIu1Kn95wyNGtI6Z_pW44jPK8 ./credentials.json > /tmp/sheet-data.json
```

스프레드시트 ID는 `.claude/settings.local.json`의 allow 목록에서 확인 가능. `credentials.json`은 리포 루트에 존재.

### 3단계: 현재 주차 식별

- 오늘 날짜(Asia/Seoul) 기준 가장 가까운 토요일(또는 당일이 토요일이면 당일)을 기준으로 한다.
- `주간현황` 시트의 마지막 행이 현재 주차 데이터다. `일자` 컬럼이 `YYYY.MM.DD, 토` 또는 `M/D/YYYY` 형식.
- **Week 넘버(NW)**와 **일자**를 확인한다. 이 값들이 파일명·frontmatter에 들어간다.

### 4단계: 핵심 숫자 추출

아래 워크시트에서 데이터를 추출한다:

#### `주간현황` (현재 주차 행)

| 필드 | 컬럼 위치 |
|------|-----------|
| 총평가금 | index 2 |
| 순원금 | index 3 |
| 누적이익 | index 4 |
| 누적수익율 | index 5 |
| 연간수익(%) | index 7 |
| 월간수익(%) | index 9 |
| 주간수익(%) | index 10 |
| 주간 평가금 변동 | index 11 |
| 주간 평가금 변동율 | index 12 |
| 투자원금 | index 13 |
| 투자이익 | index 14 |
| 현재투자수익율 | index 15 |
| 주간판매수익 | index 16 |
| 배당+이자 | index 17 |
| 코스피 지수/변동율 | index 19/21 |
| 나스닥 지수/변동율 | index 23/25 |
| 사용자 코멘트 | index 27 |

**지난 주 데이터**도 같이 추출한다 (비교용).

#### `세부종목` (현재 주차 행 블록)

- `일자` 컬럼에 현재 주차 날짜가 있는 행부터, 다음 날짜가 나오기 전까지가 한 주차 블록.
- 종목별: 평가금, 수익율, 주간수익율, 평가금 비중
- `국장 합계`, `미장 합계`, `현금성 합계`, `합계` 행도 확인

#### `매매일지` (이번 주 매매)

- 현재 주차에 해당하는 날짜의 매매 내역만 필터링
- 컬럼: 일자, 종목, 수량, 구입가, 총금액, 종류(매수/매도), 이유

#### `입출금내역` (원금 변화)

- 지난주 이후 입출금 내역 확인. 순원금 변화의 근거가 된다.

#### `PER` (참고용, 선택적)

- 신규 종목 진입/비중 확대 종목이 있을 때 밸류에이션 근거로 사용

### 5단계: 스토리 축 설계

숫자에서 서사를 뽑는다. 아래 질문에 답하면서 주요 축 2~3개를 정한다:

- 이번 주 **주간 수익율 방향** (상승/하락/보합)과 **지수 대비 성과**는?
- **가장 크게 움직인 종목** 1~3개는? 왜 움직였는지 뉴스/이벤트 맥락은?
- **이번 주 매매의 주된 방향**은? (수익실현 / 신규진입 / 비중조정 / 무행동)
- **지난주 Try에서 계획한 것**이 이번 주에 실행됐는가?
- **이정표**가 있는가? (1억 돌파, 전고점 돌파, N개월 연속 상승 등)

---

### 6단계: 초안 작성 → `docs/preview/`에 저장

파일 경로: `docs/preview/{Month}-week{N}-record.md` (예: `April-week3-record.md`)

**frontmatter 스키마**:

```yaml
---
title: "{M}월 {N}주차 투자 기록 — {한 줄 서사}"
date: "YYYY-MM-DD"          # 토요일
category: "주간리포트"
tags: ["{N}W", "{M}월{N}주", "{핵심키워드1}", "{핵심키워드2}"]
description: "지수와 계좌 수익율, 한 줄 요약 (~80자)"
thumbnail: "/images/posts/{month}-week{n}.svg"
---
```

**본문 구조** (최근 포스트 템플릿을 따름):

1. **이번 주 한 줄 요약** — blockquote로 지수·계좌 주간 변동, 그 뒤 3~5 문단으로 배경 설명
2. **주간 성과** — bullet list (총평가금, 순원금, 누적수익율, 연간이익, 월간수익, 주간수익)
3. **지수 대비** 표
4. **종목별 주간 성과** 표 — 평가금/수익율/비중/주간변동
5. **이번 주 매매** 표 + 카테고리별(1./2./3.) 해설
6. **KPT 회고**
   - Keep (계속할 것) 2~3개
   - Problem (문제점) 2~3개 — 반드시 숫자·표 근거
   - Try (시도할 것) 2~3개
7. **다음 주 관전 포인트** — bullet list 4~6개 (질문형)
8. **주요 투자 기록** — 코드 블록 타임라인 (월별 요약). 이번 주 이정표 추가
9. 마지막 줄: `*이 글은 개인 투자 기록이며, 투자 권유가 아닙니다.*`

**어투** (1-A에서 학습한 발행본 패턴을 우선 적용):

- 1인칭 회고체, 격식 낮게 ("~했다", "~이다")
- **`content/posts/2026/` 의 최신 발행본 어투를 그대로 재현**한다. 같은 사실을 표현할 때 사용자가 즐겨 쓰는 종결어미·문장 길이·서술 순서를 따른다.
- 1-A 단계에서 식별한 사용자의 **삭제 경향**(과장 형용사, 메타 코멘트, 중복 요약 등)을 초안 작성 시 미리 회피한다.
- 숫자는 반드시 `주간현황` 시트와 일치시킨다. 추정·반올림 금지.
- 지수·종목 변동에 맥락(뉴스/이벤트)을 덧붙이되 과장·예측 금지
- 이모지 사용하지 않음

### 7단계: 썸네일 SVG 생성 → `public/images/posts/`에 저장

초안 frontmatter의 `thumbnail` 경로와 동일한 파일을 **반드시 새로 생성**한다. 경로: `public/images/posts/{month}-week{n}.svg` (소문자, 예: `april-week4.svg`).

**기본 규격**

- `viewBox="0 0 800 600"`, `width="800" height="600"`
- 크기 3~6KB 수준의 순수 SVG (외부 이미지·폰트 의존 없음)
- **텍스트 금지** — 어떤 텍스트 요소(`<text>`)도 넣지 않는다. 순수 비주얼만.
- 색상은 다크 톤 그라데이션 + 강조색 1~2개로 구성한다
- `<defs>` 안에 `linearGradient` / `radialGradient` / `filter`(softblur, starblur 등) 선언 후 재사용

**디자인 규칙: 이번 주 스토리 축을 비주얼 메타포로 표현**

5단계에서 정한 스토리 축을 시각화한다. 기존 포스트 활용 예시:

| 서사 | 비주얼 메타포 |
|------|--------------|
| 첫 투자·신규 진입 | 은하수/별자리 (깊은 남색 + 보랏빛 성운) |
| 반등·이정표·1억 돌파 | 일출 (어둠 → 보라 → 주황 → 금빛 그라데이션 + 태양 + 물 반사) |
| 전쟁·하락·변동성 | 태풍·번개·거친 파도 |
| 조정·재정비 | 저녁 노을·정적인 수평선 |
| 분산·신규 편입 | 여러 개의 빛줄기·별자리 군집 |

**구성 요소 (선택적 조합, 기존 파일 참고)**

- 배경 그라데이션 (전체 rect)
- 천체: 별 40~60개(크기·불투명도 변주) + 밝은 별 3~5개(`starblur` 필터)
- 빛·후광: `radialGradient` + `glow` 필터 (태양·달·은하 중심)
- 실루엣: 산 폴리곤 2~3겹, 나무·도시·건물 밑단 실루엣
- 반사: 하단 수면 영역 + 태양·달 반사 타원
- 십자형 별빛 (가장 밝은 별 위)

**참고 파일**

- `public/images/posts/april-week1.svg` — 은하수 테마 (다크 보라+남색, 도시 실루엣)
- `public/images/posts/april-week2.svg` — 일출 테마 (보라→주황→금빛, 산·물 반사)
- `public/images/posts/march-week4.svg` — 조정 테마

새 SVG를 만들 때 이 파일들의 구조(defs → 배경 → 천체 → 실루엣 → 반사)를 차용하고, 팔레트·구도만 이번 주 서사에 맞게 바꾼다.

**저장 후 확인**

- 파일이 생성됐는지 `ls -la public/images/posts/` 로 검증
- frontmatter의 `thumbnail` 경로와 정확히 일치하는지 확인

### 8단계: 데이터 정합성 검증

숫자는 정확해야 한다.

초안 저장 후, 본문의 모든 숫자는 `주간현황` 시트 원본과 비교한다:

- 총평가금, 순원금, 누적수익율, 주간수익율(변동율), 코스피·나스닥 지수/변동율

불일치 발견 시 즉시 수정. 사용자에게 검증 결과를 간략히 보고한다.

## 주의 사항

- `content/posts/2026/`에 **직접 쓰지 않는다**. 반드시 `docs/preview/`에 먼저 저장한다.
- 사용자가 발행 승인 전에는 git add/commit 하지 않는다.
- 시트 컬럼 위치는 스키마 변경에 취약하다. `주간현황` 헤더 행(index 1)으로 컬럼명을 확인 후 추출할 것.
- 이번 주 매매가 없으면 "이번 주 매매" 섹션에 "매매 없음"이라고 명시. 표 생략 가능.
- `thumbnail` 경로는 `/images/posts/{month}-week{n}.svg` 규칙을 따른다. **7단계에서 실제 파일을 함께 생성해 놓는다.**
- SVG에는 텍스트(`<text>` 요소)를 넣지 않는다. 블로그 카드 레이아웃이 텍스트를 별도로 렌더링한다.
